# PreOrder Store

Учебное desktop-приложение интернет-магазина на C#, .NET 10, Avalonia UI 12, EF Core и SQLite. Каталог открывается без аккаунта: гость может искать товары, добавлять в избранное и собирать временную корзину. В карточке каждого товара есть отдельная страница с фото/иллюстрацией, описанием, ценой, наличием, избранным и действием «Добавить в корзину». Первая покупка предлагает вход или регистрацию; гостевую корзину затем можно перенести в аккаунт.

Каталог загружается из публичного [DummyJSON Products API](https://dummyjson.com/docs/products), синхронизируется с SQLite и отображается из локальной базы. При недоступности сети сохранённый каталог остаётся доступным. DummyJSON — источник placeholder-данных, не настоящий магазин; API-цены не являются рублёвыми предложениями, а постоянный множитель `90` используется только для учебного отображения.

В каталоге сразу создаются только 12 карточек; следующие порции добавляются по кнопке «Показать ещё». Фото из сети не загружаются в каталоге, корзине или истории: там используются лёгкие локальные SVG-заглушки. Настоящее фото запрашивается при открытии отдельной страницы товара, не более четырёх запросов одновременно, а bitmap декодируется вне UI-потока. Нажатие на изображение или название (кнопка «Подробнее о товаре») открывает детальную страницу. В корзине есть анимированные состояния добавления и удаления строки, обновление количества и счётчика. Избранное работает и для гостя (текущий запуск), и для аккаунта (SQLite).

Управление ассортиментом не показывается обычному покупателю. Первый аккаунт, созданный на устройстве, получает локальную роль администратора; последующие аккаунты — покупатели. На существующей базе миграция сохраняет доступ владельцу, назначая роль самому раннему аккаунту. Только администратор видит форму добавления и может удалить вручную созданный товар, если он не используется корзиной или историей. Позиции сохраняются при синхронизации API; чужие товары DummyJSON удалить нельзя.

Оплата является симуляцией: банковские реквизиты не запрашиваются, внешний платёжный сервис не вызывается, деньги не списываются. Подтверждение создаёт локальные записи покупок в SQLite. Наличие, цена и заказ не являются коммерческой офертой.

## Запуск

Нужен .NET 10 SDK. Из корня клонированного репозитория:

```bash
dotnet restore PreOrderStore.sln
dotnet build PreOrderStore.sln
dotnet test PreOrderStore.sln
dotnet run --project PreOrderStore/PreOrderStore.csproj
```

При запуске EF Core применяет миграции к локальной базе: `%LOCALAPPDATA%/PreOrderStore/preorder-store.db` на Windows или к пользовательской папке приложения на другой ОС. Сначала отображается локальный кэш; загрузка DummyJSON запускается в фоне. Кнопка «Обновить товары» повторяет синхронизацию.

## Покупка и темы

1. Откройте товар, изучите описание и добавьте его в корзину или избранное. Тему можно переключить кнопкой вверху.
2. Добавьте позиции в корзину как гость; анимация подтверждает изменение количества.
3. Нажмите «Перейти к покупке». Создайте профиль или войдите; гостевая корзина и гостевые избранные переносятся в аккаунт.
4. Нажмите «Подтвердить демо-оплату». Приложение сохранит покупку и покажет её в истории, но не спишет средства.
5. Только первый зарегистрированный аккаунт (локальный администратор) может открыть «Добавить товар» и управлять локальными позициями. Обычные покупатели не видят эти инструменты. Товары DummyJSON можно просматривать и покупать в демонстрации, но нельзя удалять как будто это ваш API.

Аккаунты, аккаунтные корзины, избранное и покупки хранятся на этом устройстве. Пароли сохраняются как salted PBKDF2 hash; это не серверная учётная запись.

## Архитектура

`Domain` содержит сущности товара, пользователя, корзины, избранного и покупки. `Data` — контекст SQLite и EF migrations. `Infrastructure/DummyJsonProductProvider.cs` получает API-данные; `CatalogSyncService` идемпотентно обновляет каталог и не перезаписывает локальные позиции. `StoreService` управляет каталогом, избранным, локальными товарами, корзиной и транзакционной покупкой. `AuthService` отвечает за локальную регистрацию/вход и назначение роли. `ViewModels` содержит состояния гостя, аккаунта и экранов. `Views` реализует Avalonia XAML, SVG-иконки, runtime-переключение тем и короткие переходы. Сетевые фотографии загружаются только на странице выбранного товара; каталог использует локальные заглушки.

## Проверки и ограничения

Последняя проверка: `dotnet build PreOrderStore.sln` успешна, `dotnet test PreOrderStore.sln` — 16/16. Проверки охватывают сервисные правила корзины/покупки, роли владельца, изоляцию аккаунтов, избранное, синхронизацию и безопасное удаление локальных товаров. GUI рекомендуется показать и проверить на целевой Windows-машине перед защитой.

Проект не включает production API, облачную синхронизацию, подтверждение почты, реальные цены/остатки, платёжный шлюз, доставку или обязательства продавца. Для настоящего магазина потребуются backend, авторизация на сервере, контролируемый каталог и интеграция платежей.
