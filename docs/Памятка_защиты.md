# Памятка к защите курсовой работы

## 1. Коротко о проекте

**PreOrder Store** — настольное приложение-каталог для просмотра товаров и демонстрации сценария предзаказа. Это учебный проект, а не работающий интернет-магазин: каталог берётся из публичного DummyJSON, цены ориентировочно пересчитываются множителем 90, а Demo Bank только имитирует подтверждение платежа. Реальные деньги и реквизиты карт не используются.

Технологии: C#, .NET 10, Avalonia UI 12, архитектура MVVM, Entity Framework Core и SQLite. Для проверки бизнес-логики есть xUnit-тесты.

## 2. Что за что отвечает

| Часть проекта | Назначение |
|---|---|
| `PreOrderStore/Views/MainWindow.axaml` | Разметка главного окна: навигация, каталог, корзина, карточка товара, авторизация и оплата. |
| `PreOrderStore/ViewModels/MainViewModel.cs` | Состояние экрана и команды: фильтры, переходы, добавление и удаление товаров, переключение темы и запуск оформления. |
| `PreOrderStore/Domain/Models.cs` | Модели покупателя, товара, корзины, избранного и предзаказа, а также статусы предзаказа. |
| `PreOrderStore/Data/StoreDbContext.cs` | Таблицы, индексы, внешние ключи и ограничения SQLite; миграции применяются при запуске. |
| `PreOrderStore/Services/AuthService.cs` | Регистрация и вход. Пароль хранится не в открытом виде: применяется соль и PBKDF2-HMAC-SHA256. |
| `PreOrderStore/Infrastructure/DummyJsonProductProvider.cs` | HTTP-запросы к DummyJSON, преобразование каталога, загрузка сведений о товаре и локальные русские описания. |
| `PreOrderStore/Services/CatalogSyncService.cs` | Обновление каталога в SQLite и получение подробностей товара через провайдер. |
| `PreOrderStore/Services/StoreService.cs` | Избранное, сохранённая корзина, остатки, создание локальных товаров, предзаказы и очистка корзины после подтверждения. |
| `PreOrderStore/Services/DemoBankPaymentService.cs` | Запуск Demo Bank и проверка его ответа через локальный именованный канал. |
| Репозиторий `demo-bank` | Второе Avalonia-приложение с экраном подтверждения или отмены демонстрационного платежа. |

## 3. Как работает приложение

1. `Program.cs` настраивает зависимости, открывает пользовательскую SQLite-базу и запускает EF Core migrations.
2. Сначала показывается локальный кэш товаров. Затем каталог синхронизируется с DummyJSON; ошибка сети не должна удалять сохранённые данные.
3. Каталог отображает товары порциями — до восьми карточек, по четыре в строке. Изображения загружаются лениво и ограниченно, а UI не создаёт сразу карточки для всего каталога.
4. Карточка товара открывает полную страницу с описанием, фото, примерной оценкой и отзывами источника. Эти отзывы — демонстрационные данные DummyJSON, не отзывы покупателей данного магазина.
5. Гость может просматривать товары и собирать временную корзину. При оформлении появляется центральная форма входа/регистрации. После входа гостевые позиции переносятся в аккаунт.
6. Аккаунтная корзина, избранное и история связаны с локальным покупателем и сохраняются в SQLite. Первый аккаунт без существующего администратора получает роль администратора; остальные аккаунты — покупатели.
7. Для оплаты магазин открывает отдельное приложение Demo Bank. После явного подтверждения и проверки одноразового ответа магазин транзакционно создаёт предзаказ и очищает корзину. Отмена или ошибка оставляет корзину без изменений.

## 4. Как запустить перед защитой

Нужен .NET 10 SDK. Репозитории должны быть клонированы в соседние папки, чтобы приложение нашло проект Demo Bank:

```bash
git clone https://github.com/ARTYR1387/preorder-store.git
git clone https://github.com/ARTYR1387/demo-bank.git
cd preorder-store
dotnet restore PreOrderStore.sln
dotnet build PreOrderStore.sln
dotnet test PreOrderStore.sln
dotnet run --project PreOrderStore/PreOrderStore.csproj
```

Если `demo-bank` расположен отдельно, задайте переменную `PREORDER_DEMO_BANK_PROJECT` с полным путём к `DemoBank.csproj`. Приватные репозитории доступны только пользователям, которым владелец выдал доступ.

База создаётся в пользовательской папке LocalApplicationData, в подкаталоге `PreOrderStore`, под именем `preorder-store.db`. Перед демонстрацией проверьте вход в аккаунт, сеть для первого заполнения каталога и запуск Demo Bank. Если сеть недоступна, показывайте уже сохранённый каталог.

## 5. План демонстрации преподавателю

1. **Старт без аккаунта.** Показать каталог из четырёх колонок, переключение светлой/тёмной темы, поиск, фильтр и сортировку.
2. **Карточка товара.** Нажать на карточку целиком. Показать русское описание, фотографии, цену и примерные отзывы, пояснив, что они загружаются из учебного источника.
3. **Избранное и корзина.** Поставить и снять SVG-сердце. Нажать «плюс», показать изменение количества/анимацию и фото товара в корзине; затем уменьшить количество, удалить одну позицию и очистить корзину.
4. **Авторизация только при оформлении.** Добавить гостевой товар и перейти к покупке. Показать, что магазин скрывается за центральной формой. Войти или зарегистрироваться и показать перенос гостевой корзины.
5. **Отмена платежа.** Открыть Demo Bank и нажать «Отмена». Вернуться в магазин и показать, что заказ не создан, а корзина сохранена.
6. **Подтверждение.** Повторить оформление, нажать «Подтвердить демо-платёж» и показать запись в истории. Ещё раз подчеркнуть, что деньги не переводились.
7. **Роли.** Первым аккаунтом показать инструменты администратора и создание локального товара. Войти обычным покупателем и показать, что управление каталогом ему недоступно. Для чистой демонстрационной базы первый созданный аккаунт становится администратором; миграция также назначает роль самому раннему существующему аккаунту, если администратора ещё нет.
8. **Завершение.** Коротко объяснить схему SQLite: `Customers`, `Products`, `CartItems`, `Favorites`, `PreOrders`; показать приложенные диаграммы и сообщить результат тестов.

## 6. Возможные вопросы и короткие ответы

**Для чего нужен проект?** Для демонстрации каталога, локального хранения, ролей, корзины и полного пользовательского сценария предзаказа в desktop-приложении.

**Почему используется SQLite?** База работает локально, не требует отдельного сервера, сохраняет каталог и аккаунтные данные между запусками. EF Core migrations позволяют обновлять структуру.

**Что делает DummyJSON?** Это источник примерных товаров для разработки. Он не продаёт товары и не подтверждает реальные цены или остатки. Если сеть недоступна после синхронизации, используется SQLite-кэш.

**Почему гость может просматривать каталог?** Для просмотра и временной корзины аккаунт не нужен. Вход запрашивается при оформлении, когда корзина и история должны принадлежать конкретному пользователю.

**Как хранятся пароли?** Для каждого пароля генерируется случайная соль; применяется PBKDF2-HMAC-SHA256 с 310 000 итераций. При входе проверка сравнивает хэши с постоянным временем. Это локальная учебная аутентификация, не серверная система.

**Почему первый пользователь — администратор?** Так удобно демонстрировать управление локальным каталогом без отдельной настройки ролей. В реальном продукте право администратора выдаётся защищённым серверным способом.

**Demo Bank — настоящий банк?** Нет. Это второе локальное приложение. Оно показывает сумму и состав операции, а затем отправляет подтверждение через named pipe. Карты, банковские счета и реальные платежи отсутствуют.

**Как магазин проверяет ответ Demo Bank?** Используются идентификатор платежа, сумма и случайный одноразовый токен; приложение проверяет совпадение данных и токена. Только подтверждённый результат запускает транзакционное создание заказа.

**Что происходит при отмене?** Заказ не создаётся, корзина не очищается; пользователь может повторить оформление.

**Как обеспечена целостность БД?** Внешние ключи связывают корзину, избранное и предзаказы с покупателями и товарами. Уникальные индексы предотвращают повтор email и дубли одной позиции в аккаунтной корзине/избранном; положительное количество проверяется ограничениями.

**Что не готово для реального магазина?** Нет серверной части, проверки email, реального источника цен и наличия, доставки и платёжного шлюза. Demo Bank лишь учебная симуляция.

**Как проверено приложение?** В репозитории есть 21 автоматический xUnit-тест бизнес-логики. Перед сдачей также следует лично проверить графические сценарии на компьютере, где будет защита.
