## Аннотация

Разработано настольное приложение каталога и демонстрационной покупки PreOrder Store. Пользователь может начать работу без регистрации, открывать подробную страницу товара, добавлять позиции в избранное и собирать временную гостевую корзину. При первой попытке оформить покупку программа предлагает вход или создание локального аккаунта; после аутентификации гостевые позиции корзины и избранного переносятся в аккаунт. Реализовано добавление локальных товаров и ограниченное удаление собственных позиций каталога. Покупка завершается отдельным экраном демонстрационной оплаты без банковских реквизитов и списания средств.

Каталог получен из DummyJSON Products API. Загруженные карточки сохраняются в SQLite и отображаются из локальной базы данных, поэтому каталог остаётся доступен при временном отсутствии сети. Интерфейс содержит поиск, фильтры, сортировку, светлую и тёмную темы, оригинальные SVG-иконки, анимации добавления/удаления строк корзины и перехода на страницу товара. Реализованы EF Core migrations, локальные аккаунты с salted PBKDF2-хэшированием, избранное, локальный CRUD каталога, корзина и история покупок. Решение собирается, 15 автоматических тестов проходят.

## 1. Введение

### Актуальность и проблема

Удобная программа-каталог должна показывать товары, помогать находить подходящую позицию, сохранять выбранные товары и позволять пройти понятный сценарий покупки. При этом экранный сценарий важно отделять от реальной коммерческой операции: запись в учебной базе не доказывает наличие товара и не создаёт обязательства магазина.

Проект объединяет desktop UI, сетевое получение данных, локальное хранение, аутентификацию, корзину и фиксацию покупки. Каталог сначала читается из SQLite, затем обновляется по HTTP. Гость может исследовать витрину и подготовить корзину. Локальная учётная запись запрашивается при первой покупке, когда нужно сохранить владельца корзины и истории.

### Цель, задачи, объект и предмет

**Цель работы** — разработать desktop-приложение с каталогом из API, локальным кэшем, гостевым режимом, корзиной и демонстрационной покупкой.

Для достижения цели требовалось: спроектировать архитектуру приложения; реализовать загрузку и преобразование JSON-данных; сохранять и обновлять каталог по внешнему идентификатору; выдавать старый кэш при ошибке сети; создать гостевой сценарий и локальную регистрацию; связать корзину и историю с аккаунтом; выполнить покупку в учебном режиме; добавить переключение темы; проверить правила работы сервисов тестами.

**Объект** — процесс выбора товара и оформления покупки в настольном приложении. **Предмет** — способы взаимодействия Avalonia-клиента с внешним API, локальной SQLite-базой, пользовательской сессией и бизнес-логикой корзины.

## 2. Анализ предметной области

Основные сущности сценария — каталог, корзина, пользователь и покупка. Каталог общий для всех пользователей и обновляется из внешнего источника. В гостевом режиме корзина временная и хранится в памяти процесса. При регистрации или входе позиции копируются в пользовательскую корзину SQLite. После подтверждения демо-оплаты создаются записи покупок для текущего пользователя.

DummyJSON описывает Products API как источник примерных данных для разработки и тестирования. В документации перечислены поля товара, включая идентификатор, название, описание, категорию, цену, остаток, thumbnail и изображения; endpoint списка поддерживает `limit`, `skip` и выбор полей `select` [1]. В реализации запрашиваются все доступные позиции, необходимые приложению поля сохраняются в SQLite. Полученные значения цены нельзя трактовать как коммерческие рубли: проект применяет постоянный множитель 90 только для учебного отображения суммы в рублях.

DummyJSON не является продавцом и его каталог/stock не дают подтверждения доступности товара. Созданная в приложении запись покупки остаётся локальной демонстрацией. Подключения к банковской системе, реальному магазину и службе доставки нет.

## 3. Требования к системе

### Функциональные требования

1. При запуске прочитать каталог из локальной SQLite-базы, а синхронизацию с DummyJSON выполнить в фоне.
2. Получить товары из HTTP API, валидировать обязательные поля, преобразовать цену в условное отображение RUB и сохранить/обновить товар по внешнему ID.
3. При отсутствии сети сохранить существующий каталог и показать его пользователю; предоставить кнопку повторной синхронизации.
4. Разрешить гостю просматривать каталог, открывать карточки, пользоваться поиском и добавлять товар во временную корзину.
5. Запрашивать регистрацию или вход на этапе первой покупки; позволять закрыть форму и продолжать как гость.
6. Переносить гостевые позиции в корзину аккаунта после успешной аутентификации.
7. Предоставить экран демонстрационной оплаты без банковских реквизитов; по подтверждению записывать покупку в SQLite и очищать корзину транзакционно.
8. Отображать историю покупок только вошедшего пользователя, а также состояние демо-оплаты.
9. Переключать светлую и тёмную темы, предоставлять фильтрацию по категории/наличию и сортировку.
10. Открывать отдельную страницу товара с описанием, ценой, остатком, изображением/иллюстрацией, избранным и добавлением в корзину.
11. Сохранять избранные товары аккаунта в SQLite; поддерживать гостевое избранное до завершения текущего сеанса и его перенос после аутентификации.
12. Создавать товары локально, не перезаписывать их синхронизацией DummyJSON и разрешать удаление только локальных позиций, не используемых корзиной или историей.

### Нефункциональные требования

Данные каталога должны оставаться доступными после завершения приложения. Идемпотентная синхронизация должна обновлять существующие товары без появления дубликатов. Перед записью покупки сервис проверяет доступность и остаток. Данные пользователя изолируются по CustomerId. Интерфейс должен явно показывать границы учебной оплаты и не просить вводить банковские данные. Ошибка HTTP не должна очищать локальный каталог. Начальная отрисовка не должна создавать визуальные элементы для всего внешнего каталога сразу; сетевые thumbnails не должны блокировать UI-поток.

### Ограничения

Система рассчитана на учебную демонстрацию и локальную базу одного устройства. Локальный аккаунт не подтверждает почту и не синхронизируется с сервером. Цена API пересчитывается фиксированным множителем 90, а не текущим валютным курсом. Остаток DummyJSON — sample value; приложение не устанавливает реальный резерв. Демо-оплата лишь маркирует локальную запись как подтверждённую в учебном интерфейсе и не вызывает платёжную систему.

## 4. Проектирование

### Архитектура

Решение содержит приложение `PreOrderStore` и тестовый проект `PreOrderStore.Tests`.

- `Domain` — модели продукта, покупателя, позиции корзины и покупки.
- `Data` — EF Core `StoreDbContext`, SQLite и миграции схемы.
- `Infrastructure/DummyJsonProductProvider.cs` — HTTP-клиент и JSON DTO для API.
- `Services/CatalogSyncService.cs` — синхронизация внешних товаров в локальную базу.
- `Services/StoreService.cs` — чтение каталога, управление корзиной, проверки и транзакция покупки.
- `Services/AuthService.cs` — локальная регистрация и вход.
- `ViewModels` — состояние, команды, фильтры, гостевой сценарий, оплата и темы.
- `Views` — Avalonia XAML, SVG иконки, remote-thumbnail control и палитра интерфейса.

Представление отправляет пользовательские действия во ViewModel. ViewModel вызывает сервисы. Репозиторий/контекст EF Core управляет преобразованием между сущностями и SQLite. HTTP-провайдер отделён интерфейсом `IProductProvider`, поэтому источник каталога можно заменить отдельно от бизнес-логики.

### Модель данных

| Сущность | Данные и назначение |
|---|---|
| `Product` | Внутренний ключ, внешний ID DummyJSON, название, описание, категория, цена, URL изображения, количество, дата синхронизации и доступность |
| `StoreCustomer` | Имя, нормализованный email, соль и хэш пароля, дата создания |
| `CartItem` | Покупатель, товар и количество; строки аккаунтной корзины сохраняются в SQLite |
| `FavoriteItem` | Связь «покупатель—товар»; уникальная пара предотвращает дубликаты, данные аккаунта сохраняются в SQLite |
| `PreOrder` | Покупатель, товар, количество, цена-снимок, дата, статус и признак `IsDemoPaid` |

Для `Product.ExternalId` настроен уникальный индекс. Это обеспечивает соответствие одной записи товара одному внешнему идентификатору. Для email настроен уникальный индекс; пары покупатель/товар уникальны и в сохранённой корзине, и в таблице избранного. Связи корзины, избранного и покупок задаются внешними ключами. Количество ограничено положительным значением.

### Синхронизация каталога

При открытии окна сначала загружается SQLite-каталог. Затем в фоне выполняется GET к `https://dummyjson.com/products?limit=0&select=...`. Для каждого допустимого элемента API `id` становится внешним идентификатором. Сервис обновляет совпавшие строки или вставляет новые. После успешного синхронизирования каталог перечитывается из базы. Если HTTP-запрос завершился ошибкой, локальные строки не удаляются, а интерфейс показывает сообщение о резервном использовании кэша. Для отзывчивости карточки публикуются порциями по 12 записей; остаток появляется по запросу пользователя.

Поле изображения хранит URL thumbnail. `RemoteImage` получает изображение отдельно от JSON и кэширует декодированные bitmap в памяти текущего сеанса. Одновременно выполняется не более четырёх загрузок; декодирование bitmap переносится из UI-контекста в фоновую задачу. Значения цены умножаются на константу `IllustrativeRubleMultiplier = 90`. Это демонстрационное масштабирование для интерфейса, а не конвертация по финансовому курсу.

Позиции, созданные через интерфейс, получают внутренний внешний ключ с префиксом `local-`; они сохраняются в той же SQLite-базе и не участвуют в upsert по API ID. Встроенные иллюстрации загружаются как Avalonia SVG assets. При попытке удалить локальную позицию сервис проверяет, не находится ли она в корзине и не связана ли с покупками. Удаление API-товара блокируется, поскольку клиент не может удалить запись из внешнего DummyJSON.

### Пользовательские сценарии

Гостевой сценарий: запуск → просмотр каталога из кэша → фоновое обновление → добавление доступного товара в временную корзину → нажатие «Перейти к покупке» → форма регистрации/входа. Гость может пропустить регистрацию и вернуться к каталогу/корзине.

Покупка: успешная регистрация или вход → перенос временной корзины в аккаунт → показ отдельного экрана демо-оплаты → явное подтверждение → транзакционная запись покупки с ценой-снимком и `IsDemoPaid = true` → очистка аккаунтной корзины → отображение истории. Если гость отменяет форму авторизации, покупки не создаются.

### Пользовательский интерфейс

Главное окно содержит боковую навигацию, счётчик корзины, избранное, фильтры, сетку карточек, подробную страницу выбранного товара, экран создания локального товара, историю и статус сетевого обновления. Изображение или название открывает страницу с описанием, наличием, ценой, сердцем и действием добавления в корзину. Изначально визуально создаются 12 карточек; «Показать ещё» добавляет следующую порцию без перезапуска. Темы используют единую палитру DynamicResource; команда меняет набор светлых или тёмных кистей. Для карточек, переходов экранов, состояния избранного, добавления/удаления строк корзины и счётчика применяются короткие переходы прозрачности, трансформации и фона. Для интерактивных элементов используются SVG-иконки, а не эмодзи.

Экран оплаты визуально разделён и явно помечен «Учебный режим · списания нет». Он не содержит полей карты, CVV или банковских реквизитов.

## 5. Реализация

### Технологический стек

Приложение использует C# и .NET 10. Avalonia UI обеспечивает desktop-интерфейс. CommunityToolkit.Mvvm генерирует свойства и команды ViewModel. EF Core выполняет запросы и миграции; SQLite хранит записи в пользовательской папке приложения. `IHttpClientFactory` управляет HTTP-клиентом DummyJSON. Для JSON используется встроенный `System.Text.Json`.

### Аккаунты и гостевая корзина

До оформления регистрации нет. Гостевая корзина состоит из позиций в памяти процесса; при закрытии приложения она не сохраняется. После успешного входа/регистрации позиции последовательно добавляются в SQLite-корзину пользователя. Email нормализуется, соль генерируется случайно, пароль преобразуется PBKDF2-HMAC-SHA256-хэшированием. В SQLite не хранится исходный пароль. Это локальная демонстрация, а не централизованная аутентификация.

### Оформление и демо-оплата

Нажатие «Перейти к покупке» не создаёт заказ немедленно. Гость сначала проходит аутентификацию, а затем видит экран оплаты. При подтверждении сервис в транзакции повторно проверяет доступность товаров, создаёт покупки с ценой на момент операции и признаком демо-оплаты, затем очищает корзину. Неуспешная проверка оставляет данные для пользователя и показывает сообщение. Реального запроса платёжному провайдеру нет.

### Миграции

При запуске `Database.MigrateAsync()` применяет недостающие миграции. Имеющиеся сущности и история не должны удаляться для обновления версии. Миграция `DemoPaymentFlag` добавляет признак демо-оплаты существующим покупкам со значением по умолчанию `false`; миграция `CustomerFavorites` создаёт изолированную таблицу избранного с уникальным индексом по паре пользователь/товар.

Отдельно проверено: DummyJSON отдал 194 элемента; приложение под виртуальным дисплеем запустило окно, применило миграции и получило HTTP 200, а синхронизация выполнила операции SQLite. Для итоговой сдачи необходимо проверить графический интерфейс на рабочем компьютере и разрешении пользователя.

### Ручные проверки

1. При старте увидеть каталог гостем без ввода email и пароля.
2. Переключить светлую и тёмную тему; проверить читаемость текста и поверхностей.
3. Добавить товар в гостевую корзину, изменить количество, нажать кнопку покупки.
4. Создать аккаунт и проверить перенос позиций корзины, экран демо-оплаты и отсутствие полей банковской карты.
5. Подтвердить демо-оплату, проверить покупку в истории и отсутствие реального списания.
6. Закрыть окно регистрации кнопкой пропуска, убедиться, что гостевой каталог снова доступен.
7. Отключить сеть после первого обновления, перезапустить приложение и проверить отображение каталога из SQLite-кэша.
8. Нажать «Обновить товары» при доступной сети, проверить сообщение о числе синхронизированных элементов.
9. Войти другим локальным аккаунтом и убедиться, что чужая история покупок не показывается.
10. Нажать на фото или название товара, проверить отдельную страницу, описание, цену, сердце и возврат в каталог.
11. Поставить и снять сердечко; проверить отображение в разделе «Избранное», затем повторить после входа в локальный аккаунт.
12. Добавить и удалить строку корзины; проверить мягкий вход/выход строки и увеличение счётчика.
13. Добавить собственный локальный товар, обновить каталог и убедиться, что он сохранился; удалить товар, пока он не использован.
14. Убедиться, что API-товар не удаляется через локальный экран, а позиция из корзины/истории защищена от удаления.
15. Открыть каталог с большим количеством записей: сначала отображается первая порция (12 карточек); нажать «Показать ещё» и убедиться, что следующие карточки добавляются без зависания окна.

GUI-тесты — это инструкция для пользовательской проверки; они не заявляются как автоматически исполненные на целевом Windows-компьютере.

## 7. Руководство пользователя

### Установка и запуск

Установить .NET 10 SDK, клонировать репозиторий с доступом к приватному GitHub и выполнить:

```bash
git clone https://github.com/ARTYR1387/preorder-store.git
cd preorder-store
dotnet restore PreOrderStore.sln
dotnet build PreOrderStore.sln
dotnet run --project PreOrderStore/PreOrderStore.csproj
```

Для уже клонированного проекта обновить код командой `git pull origin main`. При запуске миграции создают или обновляют SQLite-базу. При наличии интернета каталог обновляется из DummyJSON; без сети показывается ранее сохранённая копия.

### Работа с приложением

Гость открывает каталог, ищет и фильтрует позиции, открывает страницу товара, ставит сердечко или добавляет товар в корзину. Раздел «Избранное» отражает гостевой выбор в текущем сеансе; после входа выбор и корзина переносятся в аккаунт. В «Добавить товар» можно создать позицию каталога; удаления API-позиций интерфейс не обещает. После входа открывается экран демо-оплаты, и только явное подтверждение создаёт локальную покупку. «Тёмная тема» меняется кнопкой рядом с обновлением каталога.

2. Обновить каталог и показать, что товары из API сохраняются в SQLite; продемонстрировать фильтры, страницу товара и переключение сердечка.
3. Переключить тему и показать каталог без потери состояния.
4. Положить товар в гостевую корзину и показать, что запрос аккаунта появляется только при покупке.
5. Зарегистрироваться; показать, как гостевая корзина привязывается к профилю.
6. Показать экран оплаты, подчеркнуть отсутствие банковских полей и реального списания, подтвердить демо-операцию.
7. Открыть историю с признаком демо-оплаты.
8. Показать «Избранное», а затем создать и удалить локальную позицию; пояснить, почему API-товар удалить нельзя.
9. Объяснить работу кэша SQLite, миграций EF Core, анимаций корзины и результат автоматических тестов.

### Возможные вопросы

**Зачем сохранять данные API в локальную БД?** SQLite поддерживает повторное открытие каталога без обязательного сетевого ответа и предоставляет локальную основу для фильтрации и заказа.

**Почему пользователь может начать без регистрации?** Просмотр каталога и подготовка корзины не требуют профиля. Аккаунт запрашивается на границе покупки, чтобы связать сохранённую корзину и историю с пользователем.

**Почему цена показана в рублях, если API выдаёт число без рублёвого предложения?** Проект применяет фиксированный коэффициент 90 исключительно для демонстрации форматирования и суммы. Это не текущий обменный курс и не цена реального магазина.

**Можно ли считать демо-оплату настоящим платёжным процессом?** Нет. Она лишь помечает запись в SQLite. Банковские данные не вводятся, деньги и API платёжного сервиса не используются.

**Что произойдёт при недоступном DummyJSON?** Синхронизация сообщит об ошибке, а сохранённые карточки останутся в локальной SQLite-базе.

**Что нужно для коммерческого использования?** Собственный backend, договорной каталог и источник остатков, server-side identity, безопасное хранение данных, реальная платёжная интеграция, обработка ошибок и правовая проверка.

## 9. Заключение

Создано desktop-приложение на Avalonia, объединяющее каталог из DummyJSON, SQLite-кэш, гостевой просмотр, страницы товаров, избранное, локальные позиции каталога, корзину и учебную оплату. Добавлены светлая/тёмная темы, SVG-иконки, анимированные состояния корзины и безопасные ограничения удаления. Регистрация запрашивается только при оформлении; внешние данные сохраняются в SQLite, а локальные записи остаются отдельными от API-синхронизации.

Сборка прошла, 15 автоматических тестов успешны. API-ответ и запуск приложения проверены в среде разработки. Работа не является реальным магазином: внешний API предоставляет sample data, а «оплата» не списывает деньги и не уведомляет продавца.
