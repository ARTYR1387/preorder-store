# Сценарии тестирования PreOrder Store

Дата проверки: 05.11.2026. Решение собирается через .NET 10 SDK; GUI-сценарии необходимо запускать и подтверждать на целевом настольном компьютере. Каталог полностью локальный, демонстрационный и не требует интернета.

## Ручная проверка desktop UI

| ID | Проверка | Действия | Ожидаемый результат |
|---|---|---|---|
| M01 | Экран регистрации | Открыть приложение, ввести email, слабый пароль и несовпадающее подтверждение | Появляется понятная ошибка валидации |
| M02 | Создание профиля | Зарегистрироваться с корректными данными | Открывается магазин; имя видно в боковой панели |
| M03 | Витрина | Проверить карточки, RUB, SVG-иллюстрации и placeholder срока | Срок обозначен как уточняемый, demo-режим очевиден |
| M04 | Поиск/фильтры | Поменять query, категорию, статус, сортировку | Список обновляется без перезапуска |
| M05 | Корзина | Добавить товар дважды и уменьшить количество | Сумма и счётчик меняются правильно |
| M06 | Checkout | Оформить содержимое корзины | Появляется запись в истории; корзина очищена; оплаты нет |
| M07 | История и отмена | Отменить ожидающий заказ | Статус изменён, операция только для текущего профиля |
| M08 | Изоляция профилей | Выйти, создать второй аккаунт | Первый аккаунт не видит заказы первого |
| M09 | Перезапуск | Закрыть и открыть приложение, выполнить вход | Сохранённые данные доступны после входа |
| M10 | Миграция | Запустить новую версию поверх предыдущего SQLite-файла | EF применяет миграцию без ручного удаления базы |

Команды проверки из корня репозитория:

```bash
dotnet build PreOrderStore.sln
dotnet test PreOrderStore.sln
dotnet run --project PreOrderStore/PreOrderStore.csproj
```

Ручные GUI-сценарии не подменяются сообщением об успешной компиляции: их следует отдельно проверить на Windows/целевой операционной системе.
